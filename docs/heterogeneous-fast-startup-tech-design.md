# 国产异构算力集群 (MetaX / Hygon) 大模型秒级冷启动与零拷贝 DMA 直灌通用技术方案

---

## 1. 架构总览与核心愿景

### 1.1 背景与普适痛点
在异构智算平台（如 MetaX N300-A 16卡集群、海光 BW1100 8卡集群）上，生产环境部署了涵盖 Dense 与超大 MoE 架构的多元模型（如 Qwen3.8-27B、DeepSeek-V4-Flash、GLM-4.7、MiniMax-M2.5/M2.7 等）。
在传统部署体系中，所有模型启动均面临致命的冷启动瓶颈：
- **启动时间漫长**：百 GB 级模型冷启动普遍耗时 **5 ~ 10 分钟**；
- **资源浪费严重**：数十张显卡在等待反序列化期间算力空转；
- **弹性伸缩困难**：无法应对线上突发流量与秒级故障自愈。

### 1.2 通用目标定位
通过构建统一的 **Offline Pre-Sharding（离线预切分） + Direct DMA Zero-Copy Loading（在线 DMA 零拷贝直灌）** 工业标准，彻底消除启动时的重复计算：
- **通用模型权重装载耗时**：从原先的 **3~8 分钟** 全面缩短至 **≤ 2 秒**；
- **平台服务端到端就绪**：整体冷启动压减至 **15 ~ 25 秒**（含 Python 解释器、通信拓扑与算子图编译）；
- **全模型与跨芯片兼容**：统一样式兼容 Dense/MoE 架构，跨沐曦（MACA）与海光（DTK）双硬件体系。

├──────────────────────────┼────────────────────────────────────────────────────────┤

### 2.1 跨模型架构特性与适配要点

| 模型族 | 代表模型 | 核心网络特征 | 预切分与直灌核心要点 |
|---|---|---|---|
| **Dense 密集模型** | Qwen3.8-27B / 72B | 规则的 Transformer 堆叠，单层参数均匀 | 权重维度规则，直接按 TP 维度切分，无稀疏路由；直灌耗时通常 `< 0.8s` |
| **超大 MoE 模型** | MiniMax-M2.5 / M2.7 | 62 层，包含多路 Sparse MoE 专家与门控网络 | 专家参数维度细切（narrow），需在 DMA 层提供非连续切片自适应对齐 |
| **混合 MLA/MoE 模型** | DeepSeek-V4-Flash | 融合 MLA 多头潜变量注意力 + 大规模细粒度专家 | 存在大量共享参数与转置投影，必须调用 `.contiguous()` 打包后再保存 |
| **超长上下文模型** | GLM-4.7-W8A8 | 动态 RoPE 与超大 KV Cache 预分配 | 优化 CUDA Graph 内存预留与 Pinned-Memory 分配 |

### 2.2 跨异构芯片底层驱动特征对比

| 硬件平台 | 算力与通信栈 | 跨进程 IPC 特性 | 推荐加载策略 |
|---|---|---|---|
| **沐曦 MetaX (N300-A)** | MACA 3.7+ / libmccl.so | 多进程并发并发申请 CUDA IPC 显存句柄存在互斥锁 | **单进程 mmap + 硬件 DMA 直灌**（规避 IPC 争用，最稳且最快） |
| **海光 Hygon (BW1100)** | DTK 2604+ / ROCm / RCCL | 共享内存 IPC 句柄支持良好，需关注 DTK 算子编译开销 | **预切分 Safetensors + Pinned-SHM / Direct DMA** 双轨机制 |

## 3. 通用四步法标准化技术路线 (The 4-Step Standard)

为彻底杜绝各模型碎片化适配导致的异常，平台确立统一的四步工程闭环：

### Step 1: 离线切分无损化 (Zero-Loss Offline Sharding)
- **拒绝手动切分，交由官方 ModelRunner 决策**：
  在各引擎（如 vLLM）中，各算子已严格编码了其分布式切片策略（RowParallel / ColumnParallel / MoE）。
- **物理注入保障 (Physical Injection)**：
  针对 vLLM 多进程隔离特性，必须在容器内物理修改 `gpu_worker.py`，注册切片提取与 `.contiguous()` 连续化落盘逻辑，坚决避免内存碎片与跨进程方法缺失。
- **全量后置校验 (Integrity Gate)**：
  导出完成后，自动统计 0 ~ N-1 每一张卡分卷物理字节，必须保证 `total_bytes >= max_span`，严禁尾部截断。

### Step 2: 二进制连续对齐打包 (SLLM Binary Alignment)
- 将各卡的离线切片权重整理为硬件友好型连续结构：
  - 固定分卷规格（推荐单卷 9GB ~ 10GB，贴合 NVMe 块对齐）；
  - 全局张量纳秒级寻址表（`tensor_index.json`），精准记录 `[offset, size, shape, stride, dtype]`。

### Step 3: 硬件 DMA 极速直灌引擎 (Direct DMA Engine)
在运行时自定义 Loader（如 `sllm_loader.py`）中实现四项核心防护：
1. **零拷贝 mmap**：各卡独立 mmap 映射本 Rank 分卷文件；
2. **跨分卷边界连续重组**：自动探测张量跨卷偏移，两段连续内存秒级拼接；
3. **标量与 0 维广播对齐**：使用 `reshape_as` 自动处理标量参数（如 `_prob_scale`）；
4. **硬件 DMA 异步直灌**：`param.data.copy_(src_tensor, non_blocking=True)`，完全绕过 CPU 编解码。

### Step 4: 平台自动化运维与监控铁律 (Platform Engineering)
1. **1:1 独立启动脚本**：
   每个模型、每个框架版本强绑定唯一脚本（如 `start_vllm_<模型名>.sh`），严禁跨模型脚本复用与参数污染。
2. **服务监控铁律 (`xssh watch`)**：
   监控模型启动终态必须使用 `xssh watch <alias> --name <model> --port <port>` 挂起探针，**绝对严禁在交互与脚本中使用 sleep 循环轮询 tail 日志**（极度消耗 Token 与算力资源）。
3. **标准命名对齐**：
   容器名、平台 `hosts.yaml` 映射名必须保持一字不差的字符级对齐。

## 4. 落地预期与量化收益

| 衡量维度 | 传统加载模式 | **通用 DMA 极速直灌模式** | 综合收益 |
|---|---|---|---|
| **权重装载时间** | 3 ~ 8 分钟（随参数量线性增加） | **0.5 ~ 2 秒**（受限于 NVMe 物理顺序读带宽） | **180+ 倍提升** |
| **启动 CPU 开销** | 16 核全满（100% CPU 占用） | **几乎为 0%**（仅发起 DMA 系统调用） | **算力零浪费** |
| **启动内存争用** | 占用数倍 Host 内存用于解压切分 | **0 GiB 额外主机内存**（mmap 虚拟内存） | **杜绝 OOM** |
| **平台弹性伸缩** | 无法做到秒级起停 | **达到 Serverless 级别的极速拉起体验** | **极致弹性** |
